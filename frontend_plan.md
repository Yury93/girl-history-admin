# План: `girl-history-front` — админка поверх API `girl-history`

Составлен 2026-07-29. **Фаза 0 реализована** (задачи #1, #2, #3, #17) — каркас собирается, гейты
зелёные, dev-сервер проверен вживую. Остальное ещё не написано.
Исследование, на котором он стоит, — `research.md`. Рабочие инструкции — `CLAUDE.md`.

## 1. Что делаем и чего не делаем

**Делаем:** админку — рабочий инструмент владельца, где он заводит профили персонажей, прикрепляет
фото-референсы, запускает генерацию хроник и правит получившуюся ленту.

**Требования пользователя (2026-07-29):**

1. архитектурно как `ai-prompt-admin` — компонентная система, Vite + vanilla TS, без фреймворков;
2. **красиво и удобно** — это личный рабочий инструмент, а не демо;
3. **входа и авторизации нет**: `ownerKey` живёт в localStorage прозрачно для пользователя;
4. генерация **по списку фото + промпт либо просто по промпту, на выбор пользователя**.

**Не делаем:** регистрацию, вход, роли; публичную страницу чтения по `publicToken` (эндпоинты есть,
клиент к ним напишем сразу, экран — потом); правок бэкенда.

**Допущение по п.4, зафиксировано явно.** Выбор «с фото / без фото» делается **на уровне профиля**:
есть у профиля референсы — все его хроники строятся с их учётом, нет — по чистому промпту. Так
устроен бэкенд сегодня (`research.md` §2), правок API не требуется. Выбор на уровне отдельной
хроники сегодня невозможен и потребовал бы менять бэкенд.

## 2. Экраны и структура

### Оболочка

Схема ровно как в админке (`ai-prompt-admin/index.html:98-127`) — сайдбар слева, вкладки справа, —
но сайдбар несёт список профилей, а вкладки относятся к выбранному профилю.

```
┌─ Сайдбар ──────────────┬─ Main ───────────────────────────────────┐
│ Профили персонажей     │ [Профиль][Референсы][Хроники][Лента]     │
│ [+ Новый профиль]      │                                          │
│                        │                                          │
│ ▸ Аня        3 хроники │   содержимое активной вкладки            │
│ ▸ Марина     1 хроника │                                          │
│ ▸ Ника       нет хроник│                                          │
└────────────────────────┴──────────────────────────────────────────┘
```

Пока профиль не выбран — вкладки скрыты, в main приглашение создать первый профиль.
Вкладка «Лента» активна только когда выбрана конкретная хроника.

## 4. Проверка плана: охота на ошибки

Прогон плана против реального кода бэкенда. Исхожу из того, что ошибки **есть**. Каждый пункт — с
местом в коде, чтобы его можно было перепроверить.

> Нумерация пунктов охоты сквозная, 1-54, и **не совпадает с номерами задач**. Ссылки на задачи
> всегда с решёткой — «#12»; голое число в левой колонке — номер пункта охоты.

### Ломает сразу, если не учесть

| #   | Что                                           | Почему ломается                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Где в плане |
| --- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 1   | **multipart vs JSON**                         | В админке на axios-инстансе глобально стоит `Content-Type: application/json` (`ai-prompt-admin/src/api/api.ts:11-14`). Создание профиля и загрузка референсов идут `FormData` — скопировав инстанс, получим сломанные загрузки                                                                                                                                                                                                                                                                            | #4, #6      |
| 2   | **`x-owner-key` из ответа**                   | Сервер генерирует ключ, если его не прислали, и кладёт в заголовок **ответа** (`http-helpers.ts:13-20`). Не прочитаем — каждый запрос новый владелец, список профилей всегда пуст. | 3   | **Префикс картинок разный в деве и на проде** | `photoUrl` и `images[].url` собираются из `PUBLIC_URL_PREFIX` (`storage-service.ts:85-87`). ### Найдено при повторной проверке плана (2026-07-29)

Отдельный прогон плана против кода. Первые три пункта — **ошибки в самом плане**, не в бэкенде.

| #   | Что                                                 | Разбор                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Где в плане |
| --- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 34  | **`generatedDays` врёт при выборочной регенерации** | Было написано «считать прогресс по `generatedDays`» без оговорок — неверно. `generatedDays` = число **всех** дней хроники (`day-repository.ts:94-96`), а `totalDays` при выборочной регенерации = длина выбранного диапазона (`chronicle-service.ts:177`). Регенерация 3 дней из 30 даст 30/3 = 1000%. ## 6. Автодеплой

Репозиторий: **`git@github.com:Yury93/girl-history-admin.git`** (создан 2026-07-29).
Локальная папка называется `girl-history-front` — расхождение намеренное и уже принятое в этом
хозяйстве: `ai-prompt-admin` лежит в репозитории `prompt-editor`.

### Топология на сервере

**Восстановлено, а не прочитано.** Пути взяты из workflow соседних проектов, а «отдаётся с `/`» —
вывод из двух наблюдений: сервер возвращает HTML админки `Lisa AI` на любой неизвестный путь, и её
workflow делает `rm -rf /var/www/admin/*`. Сам конфиг nginx не читался, SSH не использовался.
Подтвердить перед первым выкатом: `nginx -T | grep -A5 'root /var/www'`.

Первая строка — чужая, её нельзя задеть:

| Путь                              | Что это                                 | Кто владеет                              |
| --------------------------------- | --------------------------------------- | ---------------------------------------- |
| `/var/www/admin`                  | админка `Lisa AI`, отдаётся nginx с `/` | `ai-prompt-admin` → репо `prompt-editor` |
| `/root/github.com/girl-history`   | бэкенд, pm2, порт 3001                  | `girl-history`                           |
| `/root/uploads/girl-history`      | аватары и референсы, вне рабочей папки  | `girl-history`                           |
| **`/var/www/girl-history-admin`** | **наша статика — новая папка**          | этот проект                              |

Наружу: `https://95.163.176.94.nip.io/girl-history-admin/` — фронт,
`https://95.163.176.94.nip.io/girl-history/` — API. Один origin, поэтому в проде ни прокси, ни CORS
не нужны: относительные пути просто работают.

### Что делаем

1. **`vite.config.ts`: `base: '/girl-history-admin/'`.** Без этого собранный `index.html` тянет
   ассеты с корня (`/assets/index-*.js`), а там сидит чужая админка — получим белый экран.
2. **`VITE_API_BASE`**: на сборке прода `/girl-history`, в деве `/api` (через прокси на
   `127.0.0.1:3001`). Значение подставляется на этапе `pnpm run build` в workflow.
3. **`.github/workflows/deploy-admin.yml`** — по образцу `girl-history/.github/workflows/deploy.yml`,
   а НЕ по образцу `ai-prompt-admin/.github/workflows/deploy-admin.yml`: у второго нет ни preflight
   секретов, ни `concurrency`, и он молча делает `rm -rf`.
4. **`.github/workflows/ci.yml`** — на PR и не-master: `install --frozen-lockfile` + `typecheck` +
   `build`, линт и формат advisory. Копия подхода бэкенда.
5. **nginx-блок** в `deploy/nginx/girl-history-admin.conf`, additive — соседние проекты не трогает:

   ```
   location /girl-history-admin/ {
       root /var/www;                                         # НЕ alias, см. ниже
       try_files $uri $uri/ /girl-history-admin/index.html;   # SPA-fallback
   }

   # Ассеты Vite содержат хеш в имени — кешируем намертво.
   location /girl-history-admin/assets/ {
       root /var/www;
       expires 1y;
       add_header Cache-Control "public, immutable";
       access_log off;
   }

   # index.html кешировать НЕЛЬЗЯ: имя у него постоянное, а ссылки внутри — на хешированные
   # ассеты. Закешированная оболочка после выката тянет файлы, которых уже нет, → белый экран
   # у того, кто заходил раньше. Ассеты неизменяемы, оболочка — всегда свежая.
   location = /girl-history-admin/index.html {
       root /var/www;
       add_header Cache-Control "no-cache";
   }
   ```

   **`root`, а не `alias`** — намеренно. При `root /var/www` путь `/girl-history-admin/x` ложится на
   `/var/www/girl-history-admin/x` сам, потому что имя папки совпадает с префиксом URL. Связка
   `alias` + `try_files` — известная ловушка nginx: `$uri` внутри `try_files` раскрывается не так,
   как ожидается, и фолбэк ведёт себя непредсказуемо. Совпадение имени папки с префиксом URL здесь
   не случайность, а условие: **папка на диске обязана называться `girl-history-admin`.**

   Префиксный `location` длиннее, чем `/`, поэтому выигрывает у блока существующей админки —
   у nginx для префиксных совпадений побеждает самое длинное. Ставится один раз руками, как и
   конфиги бэкенда (`girl-history/deploy/nginx/`).

6. **Секреты**: `SSH_HOST`, `SSH_USERNAME`, `SSH_PASSWORD`. Никакого `ENV` — фронт статический, БД и
   ключей у него нет.

   Где их заводить — решить осознанно. У бэкенда они лежат в **Environment** `production`, и в
   workflow объявлено `environment: production` (`girl-history/.github/workflows/deploy.yml:36`).
   Существующая админка обходится обычными секретами репозитория, без `environment:`. Оба варианта
   рабочие, но **смешивать нельзя**: объявить `environment: production`, не создав само окружение в
   Settings → Environments, — значит получить пустые секреты и отказ на preflight. Для нового
   репозитория проще секреты репозитория и без `environment:`.

> Примечание к ссылкам: `girl-history/.env.production` — **локальный файл, в git его нет**
> (`.gitignore:6` закрывает `.env.*`). В документах он цитируется как свидетельство прод-настроек,
> но искать его в репозитории бесполезно. Значение `PUBLIC_URL_PREFIX=/girl-history` независимо
> подтверждено живым запросом (`research.md` §10) — это и есть основное доказательство.
