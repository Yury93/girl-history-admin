`girl-history`. Стек: Vite + TypeScript **без React/Vue**, компонентная система по образцу

совпадают намеренно — так же, как `ai-prompt-admin` лежит в репозитории `prompt-editor`.

`https://95.163.176.94.nip.io/girl-history/`.

## Процесс работы над нетривиальным запросом (ОБЯЗАТЕЛЬНО)

Применять к **КАЖДОМУ** нетривиальному запросу. Сам процесс (изучение, исследование, план, охота на
ошибки, самопроверка, ведение документов) выполнять **НЕ спрашивая разрешения**.
**Реализацию кода — ТОЛЬКО по явной команде пользователя** (п.5). Мелкие правки — без церемоний.

1. **Изучение.** Изучить всё, что касается запроса: код фронта, релевантный раздел `research.md`, при
   необходимости — **код бэкенда**, а не его документы (см. «Инварианты», п. про документы бэкенда).
   Если что-то **действительно** неоднозначно — спросить ПЕРЕД работой. Если ясно — не спрашивать.

2. **Документ запроса.** Крупная фича — отдельный `<имя>_plan.md`, поддерживать по ходу. Мелкие
   правки документа не требуют.

3. **План + задачи + ОХОТА НА ОШИБКИ.** Создать план, наполнить задачами (`TaskCreate`). Исходить из
   того, что ошибки **ЕСТЬ** — особенно в жизненном цикле данных: гонки с фоновой генерацией,
   устаревшие `updatedAt`, утечки таймеров поллинга, пересоздание компонентов. Образец разбора —
   `frontend_plan.md` §4.

4. **Самопроверка 6–10 раз** по РЕАЛЬНОМУ коду: точные `file:line`, сигнатуры, runtime-значения.
   Чётко отделять **ИЗМЕРЕННОЕ** от **ГИПОТЕЗ**.

5. **Реализация — ТОЛЬКО по команде.** Когда план готов — **ПРЕДЛОЖИТЬ**. **НИКОГДА** не писать код

## Архитектура — следовать строго

Рабочий образец каждого пункта — `ai-prompt-admin`, но с поправками из «Осознанных отличий».

- **Стек:** Vite + TypeScript, `axios`. **Без React/Vue** — прямое требование пользователя.
- **Один `index.html`**, навигация вкладками, точка входа `<script type="module" src="/src/app.ts">`.
- **Компонент = класс** в `src/modules/<фича>/<фича>-component.ts` с единым контрактом:

  ```
  constructor(containerId)  находит контейнер, вызывает renderLayout() и bindEvents()
  renderLayout()            разметка вкладки
  bindEvents()              подписки
  activate()                загрузка данных при открытии вкладки
  ```

  Компоненты создаются **лениво**, при первой активации вкладки, и переиспользуются.

- **Слои:** `компонент → api/<сущность>-api.ts → http.ts`. Компонент не зовёт axios напрямую и не
  знает про заголовки и токены.
- **Типы:** `src/types/*.ts` — зеркала DTO бэкенда. **ТОЛЬКО СТРОГАЯ ТИПИЗАЦИЯ, `any` запрещён без
  исключений** — см. раздел «Типизация» ниже.
- **Стили** — в `styles.css` классами. Инлайн-`style` в разметке компонентов не плодить.
- **Гейты перед сдачей:** `tsc --noEmit`, `pnpm run lint`, `pnpm run format:check` — все зелёные.
- **Новый экран = вертикальный срез:** тип, метод в api-модуле, компонент, регистрация вкладки в
  `app.ts`, раздел в `research.md`.

## Типизация — только строгая (ОБЯЗАТЕЛЬНО)

**`any` не используется никогда, ни в каком виде.** Требование пользователя; правило общее с
бэкендом (`girl-history/CLAUDE.md`, раздел «Типизация»), формулировки не расходить.

**Запрещено:** явный `any` в любой позиции (`x: any`, `any[]`, `Promise<any>`,
`Record<string, any>`); приведения `as any`, `<any>value`, `as unknown as T`; подавление проверок
`@ts-ignore` / `@ts-expect-error` / `eslint-disable` для `no-explicit-any`; ослабление
`tsconfig.json` или `eslint.config.js` ради прохождения гейтов.

**Вместо `any`:**

| Ситуация                                             | Решение                                                                                                                                                             |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ответ бэкенда                                        | тип из `src/types/*.ts` — зеркало DTO. Поле поменялось на бэкенде → правится тип, а не глушится проверка                                                            |
| `catch` в api-слое                                   | `catch (e: unknown)` + сужение; разбор ошибки — один на проект, в `http.ts`                                                                                         |
| `event.target`, `dataset`, результат поиска элемента | сужать через `instanceof HTMLInputElement` и т.п., а не приводить к `any`. Дженерик-форма `querySelectorAll<HTMLButtonElement>(...)` уже используется в `app.ts:76` |
| `JSON.parse`, `localStorage.getItem`                 | `unknown` → проверка формы → типизированное значение                                                                                                                |
| `CustomEvent.detail`                                 | `CustomEvent<T>` с явным `T` (образец — `app.ts:52`)                                                                                                                |

**Чем обеспечено:** `strict: true` плюс `noUncheckedIndexedAccess`, `noUnusedLocals`,
`noUnusedParameters`, `noFallthroughCasesInSwitch` (`tsconfig.json:9-13`) и
`no-explicit-any: error` в `eslint.config.js`. Здесь строгость **выше**, чем на бэкенде, — это
осознанно, назад не откатывать. Гейт `pnpm run typecheck` (`tsc --noEmit`) обязателен: `vite build`
типы не проверяет.

## Инварианты — не нарушать

- **Прокси Vite — три правила: `/api`, `/media`, `/girl-history`.** `/api` с `rewrite`, снимающим
  префикс; два остальных без rewrite. Бэкенд отдаёт ссылки на картинки относительными
  (`girl-history/src/services/storage/storage-service.ts:85-87`), и префикс в них зависит от
  окружения: локально `/media/…`, на проде `/girl-history/media/…`. Правило нужно на **оба**, иначе
  при переключении target на прод все картинки станут битыми. Подробности — `research.md` §10.
- **Target прокси по умолчанию — `http://127.0.0.1:3001`, НЕ `localhost`.** Бэкенд слушает
  `127.0.0.1`; на этой машине `localhost` резолвится в `::1`, а IPv6-loopback закрыт — соединения не
  будет. Сам target вынесен в переменную окружения, чтобы можно было целиться в прод.
- **Порт dev-сервера 5174**, не дефолтный 5173: 5173 занимает `ai-prompt-admin`, проекты
  поднимаются одновременно. Это тот же принцип, что развёл порты 3001/5434 у бэкенда.
- **`Content-Type: application/json` НЕ ставить глобально на axios-инстансе.** Создание профиля и
  загрузка референсов идут `multipart/form-data`. В `ai-prompt-admin/src/api/api.ts:11-14` заголовок
  глобальный — копировать оттуда нельзя.
- **`x-owner-key` читать из ответа и сохранять.** Сервер генерирует ключ, если клиент его не прислал,
  и возвращает в заголовке ответа (`girl-history/src/controllers/http-helpers.ts:13-20`). Не
  сохранили — каждый запрос новый владелец, список профилей всегда пуст. Ключ короче 16 символов
  сервер игнорирует.
- **Текст ошибки бэкенда — поле `error`**, не `message` (`http-helpers.ts:23-34`). Разбор ошибок —
  один на проект, в `http.ts`.
- **Экранировать любой текст, идущий в `innerHTML`.** Тексты дней приходят от LLM и от пользователя.
  Один общий `escapeHtml` в `src/ui/dom.ts`, не копия в каждом компоненте.
- **Элементы искать внутри своего контейнера**, не через глобальный `document.getElementById`: два
  компонента с одинаковым `id` тихо перехватят чужие кнопки.
- **Таймеры поллинга останавливать** на `done`/`failed`/`partial`, при уходе с вкладки и при смене
  наблюдаемого объекта. Иначе они копятся при каждом пересоздании компонента. В движке Nova это
  прогоны (`GET /engine/runs/:id`) вместо хроник — правило то же.
- ~~**`ownerToken` — секрет, а не ссылка**~~ — правило прежнего движка. С удалением `Persona` уходят
  и `ownerToken`, и `publicToken`, и публичные ссылки на чтение: движок Nova однопользовательский,
  доступ — опциональный `ADMIN_KEY` в заголовке `x-admin-key`. Сам ключ так же **секрет**: не
  показывать в ссылках и не логировать.
- **Целевая папка деплоя — только `/var/www/girl-history-admin`.** В `/var/www/admin` лежит **чужая**
  рабочая админка `Lisa AI` (проект `ai-prompt-admin`), которую nginx отдаёт с корня домена. Её
  workflow делает `rm -rf /var/www/admin/*` — скопировать его дословно, не сменив путь, значит снести
  чужой прод.
- **`base: '/girl-history-admin/'` в `vite.config.ts` обязателен.** Фронт живёт на подпути; без `base`
  собранный `index.html` тянет ассеты с корня, попадает в SPA-fallback чужой админки и получает HTML
  вместо JS — белый экран.
- **В `VITE_`-переменные секреты не класть.** Всё с этим префиксом вшивается в бандл и видно в
  исходниках страницы. Туда идёт только базовый путь API.
- **Прод-сборку локально запускать из PowerShell, НЕ из Git Bash.** ЗАМЕРЕНО 2026-07-30:
  `VITE_API_BASE=/girl-history pnpm run build` в Git Bash даёт успешную, но БИТУЮ сборку — MSYS
  считает значение путём и подставляет `C:/Program Files/Git/girl-history`, после чего все запросы
  к API уходят в никуда. Правильно: `$env:VITE_API_BASE='/girl-history'; pnpm run build`. Проверка
  одной строкой: `grep -o '.\{30\}girl-history.\{20\}' dist/assets/index-*.js`. В GitHub Actions
  (Linux) проблемы нет, поэтому автодеплой ей не подвержен.
- **Ссылки на картинки не конструировать.** `PUBLIC_URL_PREFIX` различается: локально пуст
  (`photoUrl` = `/media/…`), на проде `/girl-history` (`photoUrl` = `/girl-history/media/…`). Брать
  `photoUrl` и `images[].url` из ответа как есть, прокси в деве настраивать на оба префикса.
- **Документам бэкенда не верить на слово — проверять по коду.** `girl-history/CLAUDE.md` приведён в
  актуальное состояние 2026-07-30, но `profile-generation_plan.md` и `README.md` описывают прежний
  движок: `profile-generation_plan.md:268` даёт неверные пути правки дня и регенерации
  (`research.md` §3). Источник правды по существующему коду — контроллеры и сервисы бэкенда; по
  будущему — `girl-history/nova-engine_plan.md`.

  Эта осторожность оправдалась дважды: запись «vision не реализован» была неверна (он есть в
  `services/vision/`), запись «База пуста» — тоже (замер 2026-07-30 нашёл тестовые данные).
  Утверждение о состоянии без замера — гипотеза, а не факт.

## Оценка уверенности (ОБЯЗАТЕЛЬНО)

(что подтверждено по коду/runtime, какие остаются гипотезы). Цифра должна отражать **ИЗМЕРЕННОЕ**, а
