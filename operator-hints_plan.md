# План: встроенные подсказки для оператора

Составлен 2026-07-31. **Статус: РЕАЛИЗОВАНО 2026-07-31 по команде пользователя** (задачи
H1–H7, итог и отступления — §11). Открытые вопросы решены пользователем (§8 → Decisions),
требование «красиво с анимациями» — §4.5. Цель: оператор, не читавший ТЗ и планов,
открывает админку и быстро понимает, что за экран перед ним, зачем он и что делать сначала.

## 1. Задача

Админка — 13 экранов с доменной терминологией (слот, якорь, пул, режим, арка, эталон,
SoulId, реестр, прогон). Связи между экранами неочевидны: почему без режима не запустится
генерация, зачем план месяца, откуда берётся картинка. Нужен слой подсказок, встроенный в
интерфейс, — не отдельная вики, которую никто не откроет.

## 2. Что уже есть (ИЗМЕРЕНО, по коду)

Подсказки в проекте уже четырёх видов — новый слой должен их дополнять, не дублировать:

| Что                                | Где                                                                              | Пример                                                                                                                                                                       |
| ---------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Подзаголовок экрана                | `screenHead(title, subtitle)` — `src/ui/screen.ts:52-61`, есть у всех 13 экранов | «Сценарий дня собирается детерминированно; LLM только пишет тексты» (`generation-component.ts:50`)                                                                           |
| Подсказка у поля                   | `field(label, input, hint)` — `screen.ts:85-88`                                  | «По строке на правило. Уходит в системный промпт и в фильтр» (`character-component.ts:66`)                                                                                   |
| Предупреждающие карточки по данным | `card(..., 'card-warn')`                                                         | локации без луков (`locations-component.ts:38-43`), эталон без файла (`references-component.ts:58-66`), позиции без категории (`pools-component.ts:105-110`)                 |
| Последствия в модалках и тостах    | `confirmDialog`, `toast`                                                         | «Вместе с режимом каскадом удалится его сетка недели» (`modes-component.ts:153-160`); «Сохранено. Перегенерация теперь обойдёт этот день стороной» (`feed-component.ts:239`) |

Плюс: направляющие empty-state («Режимов нет — выполните импорт справочников»,
`modes-component.ts:72`, `week-grid-component.ts:46`), человеческие тексты ошибок в одном
месте (`http.ts:84-118`), список доступных ключей в сетке недели
(`week-grid-component.ts:73-81`).

**Вывод:** «что произойдёт, если нажать» покрыто хорошо. Не покрыто «что это вообще такое
и когда сюда заходить» — уровень экрана и уровень термина.

## 3. Чего не хватает

1. **Объяснение экрана целиком**: подзаголовок в одну строку не отвечает «когда сюда
   заходить» и «с чем экран связан».
2. **Глоссарий терминов**: слот, якорь, пул, канон, режим, арка, эпизод, отклонение,
   соцсобытие, константа, квест, лук, эталон, SoulId, реестр, прогон, зерно, рубрика,
   kind постов (main/crosspost/touch/night), статусы поста.
3. **Порядок первого запуска**: сейчас он описан только в README, в интерфейсе его нет.
4. **Проверка готовности перед генерацией**: оператор узнаёт о незаполненном справочнике
   из ошибки после запуска, а не до.

## 4. Решение — четыре слоя

Всё в архитектуре проекта: без фреймворков и внешних библиотек, тексты — статические
строки в одном типизированном модуле, разметка — через конструкторы `ui/screen.ts`.

### 4.1 Тексты — один модуль `src/help/help-texts.ts`

```ts
export interface ScreenHelp {
  /** Что это за экран и зачем. 2-4 предложения. */
  what: string;
  /** Когда сюда заходить: первый запуск / ежедневно / по сигналу. */
  when: string;
  /** Связи: что сломается или не сработает без этого экрана. */
  links: string[];
  /** Грабли: короткий список «чего не делать / о чём помнить». */
  pitfalls: string[];
}
export const SCREEN_HELP: Record<TabName, ScreenHelp> = { ... };
export const GLOSSARY: Record<GlossaryKey, string> = { ... };
```

`TabName` сейчас объявлен в `app.ts:46` — импортировать его оттуда в help-модуль нельзя
(кольцо «оболочка → компонент → help → оболочка», тот же запрет, что у `types/tab.ts:1-4`).
Перенести `TAB_NAMES`/`TabName` в `types/tab.ts`, `app.ts` реэкспортом не пользоваться —
поправить импорты (затронет только `app.ts`).

### 4.2 Панель «Что это за экран» — в каркасе, не в 13 компонентах

`screenHead()` получает необязательный `helpKey: TabName`; при его наличии рядом с
заголовком рендерится кнопка «?», раскрывающая панель с `what/when/links/pitfalls`.
Один раз в каркасе — все экраны получают одинаковое поведение, компонент лишь передаёт ключ.

Свёрнутость — в `localStorage` (`nova-admin:help-seen:<tab>`): новичку панель раскрыта при
первом открытии экрана (**решено пользователем**, Decisions п.1), после закрытия остаётся
свёрнутой. Состояние живёт вне компонента — компоненты пересоздаются при смене ключа доступа
(`app.ts:111-113`), панель не должна «вспыхивать» заново.

Раскрытие/сворачивание по клику — **классом на живом DOM-узле, НЕ через `render()`**:
полная перерисовка `innerHTML` пересоздала бы узел, и CSS-транзишн раскрытия не сыграл бы
(§6 п.8). Автораскрытая панель при первом показе появляется уже открытой, без анимации —
анимируются только действия пользователя.

Подписка на кнопку «?» — делегированная, один раз в конструкторе `BaseScreen` (`onClick` на
`this.root` по классу `.help-toggle`): `screenHead()` возвращает строку HTML и сам ничего
навесить не может, а `render()` заменяет `innerHTML` целиком — прямой слушатель не пережил бы
первую же перерисовку (тот же урок, что в `week-grid-component.ts:132-137`).

### 4.3 Гид «Как работает движок» — модалка из шапки

Кнопка в `#topbar` («Как это работает»). Внутри — статическая разметка: схема конвейера
(та же, что в README: справочники → план дня → 4 поста → модерация) и чеклист первого
запуска со ссылками-переходами на нужные вкладки. Модалка — по образцу `ui/confirm.ts`
(backdrop, Escape, клик мимо), но без кнопок подтверждения — просто закрытие.
Автопоказа при первом входе НЕТ (**решено пользователем**, Decisions п.2) — кнопка всегда
на виду. Появление и закрытие — с анимацией (§4.5); закрытие ждёт конца анимации со
страховочным таймером (§6 п.10).

Переход на вкладку из модалки/панели — **не** прямым вызовом `App` (кольцо), а
`CustomEvent<TabName>` на `document`; оболочка подписывается рядом с `setupTabs()`
(`app.ts:86-93`). Типизировать через `CustomEvent<T>` — образец уже был в прежней оболочке.

### 4.4 Термины — точечные подсказки

Хелпер `helpMark(key)` → `<span class="help-mark" tabindex="0">?</span>` с текстом из
`GLOSSARY`. Ставится выборочно: в заголовки карточек и колонок таблиц, где термин впервые
встречается на экране («Якорь», «Канон», «Зерно», «Эталон»…), — не на каждое поле.

Механика показа — **сразу красивый тултип** (переиграно требованием «красиво с анимациями»,
Decisions п.3 и п.5; вариант с нативным `title` отменён). Новый модуль `ui/tooltip.ts`:

- **один глобальный элемент** тултипа на приложение, `position: fixed` — единственный
  способ не быть обрезанным `.table-wrap { overflow-x: auto }` (§6 п.2);
- координаты от `getBoundingClientRect()` цели: под элементом, у краёв экрана —
  переворот вверх и прижим по горизонтали;
- показ/скрытие — делегированно с `document`: `pointerover`/`pointerout` (НЕ
  `mouseenter` — он не всплывает, §6 п.9) плюс `focusin`/`focusout` для клавиатуры;
- прячется при скролле и при переключении вкладки (§6 п.11);
- текст — только через `textContent` (это plain text из словаря, HTML внутри не нужен).

### 4.5 Анимации — требование «красиво» (2026-07-31)

Только CSS-транзишны и keyframes, без анимационных библиотек. Вписаться в уже существующий
словарь движений проекта, а не завести второй: ховеры `0.15s` (`styles.css:155-157`),
появление тоста `toast-in` — fade + `translateY(8px)` за `0.18s ease-out`
(`styles.css:548, 561-568`).

| Элемент                                                         | Анимация                                                                                                                                                                      |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Панель «Что это за экран»                                       | раскрытие `grid-template-rows: 0fr → 1fr` на обёртке (~0.2s ease); контент в `overflow: hidden`-вкладыше. Это анимирует «высоту по содержимому», чего `height: auto` не умеет |
| Модалка гида (и заодно `confirm.ts` — сейчас появляется рывком) | backdrop — fade `0.15s`; карточка — fade + `scale(0.96 → 1)` `0.18s ease-out`; закрытие — обратный fade с ожиданием конца (§6 п.10)                                           |
| Тултип термина                                                  | fade + `translateY(4px → 0)` `0.15s`; исчезание без задержки                                                                                                                  |
| Кнопка «?»                                                      | лёгкий ховер: цвет/фон `0.15s`, как у `.tab-btn`                                                                                                                              |

Всё движение отключается медиазапросом `@media (prefers-reduced-motion: reduce)` — одна
общая секция в `styles.css`, а не проверки в JS.

Анимация модалки затрагивает и существующую модалку подтверждения — это осознанное
расширение объёма (общий CSS-класс, `confirm.ts` не переписывается, меняется только
закрытие: удаление узла после анимации).

### Что сознательно НЕ делаем

- Интерактивные туры-обходы (driver.js и подобные) — внешняя зависимость, хрупкая привязка
  к DOM, противоречит «без фреймворков».
- Анимационные JS-библиотеки и «пружинные» эффекты — только CSS, длительности ≤0.25s:
  это рабочий инструмент, движение не должно замедлять действия.
- Подсказки с конкретными цифрами правил (70/25/5, лимиты позиций) — цифры живут в данных
  и настройках, копия в статическом тексте разъедется. В текстах — механика, не константы;
  цифра допустима только со словом «дефолт».

## 6. Охота на ошибки (заранее, по реальному коду)

1. **Кольцевой импорт `TabName`.** `app.ts` импортирует все 13 компонентов; если help-модуль
   или компонент импортирует `TabName` из `app.ts:46` — кольцо. Лечение в §4.1 (перенос в
   `types/tab.ts`). Runtime-кольцо сейчас не взорвётся (импорт типа стирается), но контракт
   `types/tab.ts:1-4` заведён именно против этого — не нарушать.
2. **CSS-тултип обрежется таблицей.** `.table-wrap { overflow-x: auto }`
   (`styles.css:922-923`) клипует абсолютное позиционирование внутри. Потому тултип §4.4 —
   ТОЛЬКО `position: fixed` с JS-координатами (один глобальный элемент); вариант
   «absolute внутри ячейки» не рассматривать вовсе.
3. **Клик по «?» не должен срабатывать как клик по строке.** `onClick` делегирован через
   `closest` (`dom.ts:44-55`): «?» внутри `[data-toggle]`-заголовка пула (`pools-component.ts:72`)
   свернёт/развернёт пул. Правило: `helpMark` не ставить внутрь кликабельных зон, либо в
   обработчике панели гасить всплытие — решить на реализации и зафиксировать.
4. **Пересоздание экрана при смене ключа** (`app.ts:108-114`): раскрытость панели держать в
   `localStorage`, не в поле компонента — иначе панель будет раскрываться заново.
5. **Перерисовка `innerHTML` целиком**: состояние «панель раскрыта в этой сессии» переживает
   `render()` только вне DOM. Подписка на кнопку «?» — делегированная, как всё в проекте.
6. **`escapeHtml` на все тексты подсказок.** Они статические, но правило проекта — без
   исключений; к тому же в текстах встречаются `<code>`-фрагменты — размечать через
   конструкторы, а не сырой HTML в словаре. Словарь хранит только plain text.
7. **Расхождение текста с поведением.** Тексты §5 утверждаются пользователем и живут в одном
   файле `help-texts.ts` — при изменении механики бэкенда обновлять их там же (директива 4).
8. **Панель нельзя раскрывать через `render()`.** Перерисовка заменяет `innerHTML` целиком —
   узел панели пересоздастся, и транзишн из §4.5 не сыграет: панель «прыгнет» вместо
   плавного раскрытия. Toggle — только `classList` на живом узле; в localStorage состояние
   пишется тут же, чтобы следующий полный `render()` (после сохранения, reload) отрисовал
   панель уже в актуальном виде без анимации.
9. **`mouseenter`/`mouseleave` НЕ всплывают** — делегировать показ тултипа с `document`
   можно только через `pointerover`/`pointerout`. Цель искать `closest('.help-mark')` и
   сверять с `relatedTarget`, иначе переходы курсора по вложенным узлам заставят тултип
   мигать.
10. **`transitionend` может не прийти** — при `prefers-reduced-motion` транзишна нет вовсе,
    у фоновой вкладки события задерживаются. Закрытие модалки, ждущее конца анимации,
    обязано иметь страховочный `setTimeout` чуть больше длительности. Для `confirm.ts` это
    критично: без страховки не выполнится `resolve`, и подтверждаемое действие зависнет.
11. **Тултип `position: fixed` не движется со скроллом.** ПОПРАВКА при реализации: в
    раскладке Nova скроллится сам документ — `body { overflow: auto }` (`styles.css:668-670`),
    а правило `.tab-content { overflow-y: auto }` (`styles.css:175-180`) перекрыто ниже
    (`styles.css:740-746`, без overflow) и не действует. Решение то же: слушатель `scroll`
    на `document` в capture-фазе (`{capture: true, passive: true}`) ловит и документ, и
    внутренние контейнеры вроде `.table-wrap`; тултип прячется первым же событием и при
    переключении вкладки.
