# girl-history-admin — админка движка Nova

Рабочий инструмент оператора контента. Бэкенд [`girl-history`](../girl-history) детерминированно
собирает «жизнь» вымышленного персонажа Новы из справочников, LLM пишет только тексты постов,
Higgsfield рисует картинки — а человек в этой админке всё это настраивает, запускает и модерирует.
**Автопубликации нет**: статус поста меняет только оператор.

Vite + TypeScript, **без React и Vue** — компонентная система по образцу `ai-prompt-admin`.

Локальная папка называется `girl-history-front`, репозиторий — `girl-history-admin`.
Расхождение намеренное, как у соседей: `ai-prompt-admin` лежит в репозитории `prompt-editor`.

## Как работает движок — чтобы понимать экраны

Конвейер одного дня:

```
справочники: режимы → сетка недели → пулы, локации, гардероб, арка, отклонения
        │  детерминированный генератор (зерно прогона, без LLM)
        ▼
план дня: слоты «утро/день/вечер/ночь» — якорь, локация, лук, выпавшие варианты
        │  каждый выпавший вариант записывается в РЕЕСТР — чтобы не повторяться
        ▼
4 поста в день (один вызов LLM):
  утреннее касание (TG) · главный пост (TikTok — единственный с картинкой)
  · вечерний кросспост (TG) · ночной пост (TG)
        │  Higgsfield — картинка main-поста (если включено)
        ▼
лента → правка руками → draft → approved → published
```

Ключевая идея: **сценарий дня не сочиняется моделью, а разыгрывается из справочников** по зерну
прогона. LLM получает уже готовый план и только пишет тексты. Поэтому большинство экранов —
справочники: качество ленты определяется ими, а не промптом.

Два следствия, которые постоянно всплывают в работе:

- **План месяца** («Отклонения» → «Сгенерировать план») раскладывает по датам отклонения,
  соцсобытия, квест и константы. Без него день соберётся, но выйдет «ровным» — генератор
  просто не найдёт записей на дату (`girl-history/src/services/engine/day-planner-service.ts:88`).
- **Реестр вариаций** — не лог, а вход генератора: правила «не повторять» смотрят в него.
  При перегенерации дня стираются только записи этого дня.

## Экраны

**Справочники** — описание жизни персонажа:

| Экран        | Что это и зачем                                                                                                                                                  |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Персонаж     | Анкета, психология, тон речи, список «никогда», константы-фишки. Уходит в кешируемый блок промпта; каждое сохранение поднимает версию (история ревизий на месте) |
| Режимы       | Сезонные режимы (лето/семестр/сессия): период дат и время слотов. **Дата без режима — генерация вернёт ошибку.** Плюс календарные события и правила реализма     |
| Сетка недели | 7 дней × 4 слота на каждый режим: якорь, локации, пулы слота. Это скелет, из которого собирается каждый день. Несколько локаций через `\|` — чередование         |
| Пулы         | Пулы вариаций и их позиции («что выпадает» в слот). Правила ротации — read-only, они разобраны из сида. Сверху — алерты об исчерпании                            |
| Отклонения   | Отклонения от нормы (проспала, дождь…), соцсобытия и **план месяца** — какие из них на какие даты выпадут                                                        |
| Локации      | Локации (у каждой `titleEn` — он идёт в англоязычный промпт картинки) и гардероб-луки. Локация без лука подсвечена: движок одежду не выдумывает                  |
| Референсы    | Фото по категориям, отметка эталона, создание SoulId для Higgsfield (только на проде — нужен публичный URL), правила генерации изображений                       |
| Арка         | Сезон: дата старта — якорь недели 1, сдвиг сдвигает весь сезон — и эпизоды по неделям                                                                            |

**Работа** — ежедневный цикл оператора:

| Экран     | Что это и зачем                                                                                                                                                                                                                  |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Генерация | Запуск прогона на день или период; чекбоксы «тексты» (LLM, стоит денег), «картинки», «перезаписывать правленые». Таблица прогонов с отчётом и «что выпало за день». Одновременно живёт один прогон, второй запуск получит 409    |
| Лента     | Посты с фильтрами. Инлайн-правка (конфликт двух вкладок ловится по `updatedAt` → 409), переходы статусов, перегенерация текста и картинки. Пост со сработавшим фильтром «никогда» подсвечен; его одобрение требует подтверждения |
| Реестр    | «В этот день, в этом слоте, из этого пула выпало это» — ответ на вопрос «почему сегодня именно это»                                                                                                                              |
| Тренды    | Ручные тренд-брифы. Бриф со статусом `new` на дату дня подставляется в промпт и после генерации становится `used`                                                                                                                |
| Настройки | Импорт справочников из сида, правила постинга/сцены/причёсок, фильтр «никогда», параметры изображений, рубрики, шаблоны промптов                                                                                                 |

Правленый пост (`isEdited`) перегенерация обходит стороной — **весь его день** пропускается,
если не поставить «перезаписывать».

Подсказки встроены в саму админку: кнопка **«Как это работает?»** в шапке открывает гид со
схемой конвейера и чеклистом первого запуска, у каждого экрана есть панель **«?»** («что это,
когда сюда заходить, грабли»), у терминов — всплывающие пояснения, а на «Генерации» кнопка
**«Проверить готовность»** до запуска показывает, чего не хватает периоду.

Для новичка есть **«Обучение»** — курс на 16 шагов в порядке первого запуска: панель-спутник
ведёт по экранам, подсвечивает нужные блоки и даёт практические задания, не блокируя
интерфейс. Прервать можно в любой момент — прогресс сохраняется, кнопка в шапке предложит
продолжить с того же шага.

## Порядок первого запуска

1. **Настройки → «Импорт (missing)»** — заполнить справочники из сида. Режим `missing` не трогает
   существующие записи; `overwrite` перезаписывает поля значениями сида и требует ввода фразы.
2. **Референсы** — загрузить файлы, отметить эталон; на проде создать SoulId. Без SoulId
   картинки сгенерируются, но внешность не будет консистентной между кадрами — референс просто
   не приложится к запросу. Совсем без картинок — только при выключенном провайдере.
3. Пройтись по **Персонажу**, **Режимам** (покрывают ли нужные даты), **Сетке недели**, **Арке**
   (дата старта!) — импорт даёт рабочие дефолты, но проверить стоит.
4. **Отклонения → «Сгенерировать план»** на месяц — иначе дни выйдут без событий.
5. По желанию **Тренды** — добавить бриф на дату.
6. **Генерация** — начать с одного дня без картинок, посмотреть «что выпало», открыть **Ленту**.
7. **Лента** — править, менять статусы. Публикация в соцсети — вне системы, статус только фиксирует факт.

## Профили персонажей

Персонажей может быть несколько: селектор в шапке переключает профиль (уходит заголовком
`x-character-id`; без выбора работает профиль по умолчанию). «+» создаёт новый профиль —
он получает копию личности дефолтного и полный набор справочников из сида, генерация и
лента у него свои. Удаление — на экране «Персонаж», с вводом имени: каскад сносит весь
контент профиля безвозвратно.

## Доступ

Входа и регистрации нет. Если на сервере задан `ADMIN_KEY`, каждый запрос обязан нести заголовок
`x-admin-key`, иначе 401; пустой `ADMIN_KEY` — админка открыта (так работает дев). Ключ вводится
в шапке и хранится в localStorage; сервер его **не выдаёт** — это общий секрет команды, в ссылки
и логи не попадает. Смена ключа пересоздаёт текущий экран.

Лимиты запросов: генерация и импорт — 15 за 15 минут, остальные изменения — 60. Превышение — 429
с внятным текстом.

## Быстрый старт (разработка)

Нужны Node 20+ и pnpm 9+, запущенный бэкенд `girl-history` на `127.0.0.1:3001`.

```bash
pnpm install
pnpm dev
```

Открывать **http://127.0.0.1:5174/girl-history-admin/**

`.env` в деве не обязателен: target прокси по умолчанию `http://127.0.0.1:3001`, а базовый путь
API вычисляется от `base` приложения. Задавать `VITE_API_BASE` в деве **не нужно**: ЗАМЕРЕНО, что
dev-сервер Vite снимает префикс `base` с пути до сопоставления с прокси, поэтому голый `/api/...`
даёт 404 — рабочий дев-адрес `/girl-history-admin/api/...`, и `http.ts` строит его сам.

Два места, где легко споткнуться, и оба не случайны:

- **`/girl-history-admin/`, а не корень.** Приложение живёт на подпути (`base` в `vite.config.ts`),
  потому что на проде рядом с корнем домена стоит чужая админка. На корне будет 404.
- **`127.0.0.1`, а не `localhost`.** Без явного `server.host` Vite биндится на `[::1]`, то есть
  только IPv6 — а на машине разработчика IPv6-loopback закрыт, и страница не откроется, хотя
  в консоли будет бодрое «ready». Тот же инвариант, из-за которого у бэкенда `HOST=127.0.0.1`.

## Как устроен код

```
index.html + styles.css     оболочка, две группы вкладок, вся вёрстка классами
src/app.ts                  вкладки, ленивые компоненты, контракт с deactivate()
src/api/http.ts             единственная точка выхода в сеть: x-admin-key, разбор ошибок из поля error
src/api/engine-api.ts       клиент API, сгруппированный по разделам админки
src/state/admin-key.ts      ключ доступа в localStorage
src/types/engine.ts         зеркала DTO бэкенда — источник правды там
src/help/help-texts.ts      тексты подсказок оператора: панели экранов + глоссарий терминов
src/ui/                     escapeHtml, тосты, модалки, тултип, гид, BaseScreen + конструкторы разметки
src/modules/<экран>/        13 компонентов экранов
```

Экран — класс поверх `BaseScreen` (`src/ui/screen.ts`): `load()` грузит данные, `render()` рисует,
каркас берёт на себя спиннер и показ ошибки. Компоненты создаются лениво при первом открытии
вкладки; всё, что опрашивает сервер (поллинг прогона), обязано гаситься в `deactivate()`.

Правила, которые здесь не нарушают:

- **`any` запрещён без исключений** — `strict` + `no-explicit-any: error`; `catch (e: unknown)`.
- **Любой текст в `innerHTML` — через `escapeHtml`**: тексты приходят от LLM и от людей.
- Элементы ищутся **внутри контейнера компонента**, подписки — делегированные (`onClick` на корень):
  `render()` заменяет innerHTML целиком, прямые слушатели не пережили бы перерисовку.
- Глобального `Content-Type: application/json` на axios нет — загрузка референсов идёт multipart.
- Ссылки на картинки берутся из ответа как есть: префикс `/media/…` ↔ `/girl-history/media/…`
  зависит от окружения, конструировать их нельзя.

## Деплой

Статика в `/var/www/girl-history-admin`, отдаётся nginx по пути `/girl-history-admin/`
на том же origin, что и API (`https://95.163.176.94.nip.io/girl-history-admin/`).

- `.github/workflows/ci.yml` — на PR и не-master: `install --frozen-lockfile` + `build`;
  линт и формат advisory.
- `.github/workflows/deploy-admin.yml` — на push в `master` и вручную: preflight секретов,
  сборка с `VITE_API_BASE=/girl-history`, проверка префикса ассетов, SCP, атомарная подмена
  папки, `nginx -t` и reload.

**Что нужно сделать один раз, иначе автодеплой не заработает:**

1. Завести Environment `production` (Settings → Environments) с секретами `SSH_HOST`,
   `SSH_USERNAME`, `SSH_PASSWORD`. Имя окружения обязано совпадать с объявленным в
   `deploy-admin.yml`: секреты окружения видны только его job, при расхождении молча придут пустыми.
2. Поставить nginx-блок из `deploy/nginx/girl-history-admin.conf` в server-блок домена,
   затем `nginx -t && systemctl reload nginx`. Workflow конфиг не разворачивает.

Проверить после выката:

```
curl -I https://<домен>/girl-history-admin/   # 200, страница админки
curl -I https://<домен>/                      # по-прежнему чужая админка Lisa AI
```

**`/var/www/admin` — чужая папка**: там рабочая админка соседнего проекта. Её workflow делает
`rm -rf /var/www/admin/*`; копировать его, не сменив путь, значит снести чужой прод.

Прод-сборку локально запускать **из PowerShell, не из Git Bash**: MSYS превращает
`VITE_API_BASE=/girl-history` в `C:/Program Files/Git/girl-history`, сборка проходит, но битая.
Правильно: `$env:VITE_API_BASE='/girl-history'; pnpm run build`.
