# girl-history-admin

Админка к бэкенду [`girl-history`](../girl-history): профили вымышленных персонажей,
фото-референсы, генерация хроник «что она делала каждый день» и правка получившейся ленты.

Vite + TypeScript, **без React и Vue** — компонентная система по образцу `ai-prompt-admin`.

Локальная папка называется `girl-history-front`, репозиторий — `girl-history-admin`.
Расхождение намеренное, как у соседей: `ai-prompt-admin` лежит в репозитории `prompt-editor`.

## Требования

- Node 20+ (проверялось на 24), pnpm 9+
- запущенный бэкенд `girl-history` — локально на `127.0.0.1:3001` либо прод

## Быстрый старт

```bash
pnpm install
cp .env.example .env      # при необходимости поправить адрес бэкенда
pnpm dev
```

Открывать **http://127.0.0.1:5174/girl-history-admin/**

Два места, где легко споткнуться, и оба не случайны:

- **`/girl-history-admin/`, а не корень.** Приложение живёт на подпути (`base` в `vite.config.ts`),
  потому что на проде рядом с корнем домена уже стоит чужая админка. На корне будет 404.
- **`127.0.0.1`, а не `localhost`.** Без явного `server.host` Vite биндится на `[::1]`, то есть
  только IPv6 — а на машине разработчика IPv6-loopback закрыт, и страница не откроется, хотя
  в консоли будет бодрое «ready». Тот же инвариант, из-за которого у бэкенда `HOST=127.0.0.1`.

## Как это устроено

```
index.html + styles.css    оболочка и тема, вся вёрстка классами
src/app.ts                 вкладки, ленивые компоненты, контракт с deactivate()
src/api/                   http.ts + клиент на каждую сущность
src/state/                 ownerKey в localStorage, общий стор выбранного профиля
src/types/                 зеркала DTO бэкенда + лимиты для валидации на клиенте
src/ui/                    escapeHtml, тосты, модалка подтверждения, форматирование
src/modules/<фича>/        компоненты вкладок
```

Компонент — класс с одним контрактом: `constructor(containerId)` → `renderLayout()` →
`bindEvents()`, данные грузятся в `activate()`, таймеры гасятся в `deactivate()`.

## Связь с бэкендом

Маршруты бэкенд отдаёт **без** префикса `/api` — префикс снимает dev-прокси, а на проде nginx
отдаёт сервис по пути `/girl-history`.

| Переменная        | Дев                     | Прод            |
| ----------------- | ----------------------- | --------------- |
| `VITE_API_TARGET` | `http://127.0.0.1:3001` | —               |
| `VITE_API_BASE`   | `/api`                  | `/girl-history` |

Прокси настроен на три пути: `/api` (со снятием префикса), `/media` и `^/girl-history/`.
Последний — **регулярное выражение, и слэш на конце обязателен**: строка `'/girl-history'`
матчилась бы по префиксу и захватила бы `/girl-history-admin/`, то есть ассеты самого
приложения ушли бы на бэкенд.

**Ссылки на картинки не конструировать.** Бэкенд отдаёт их относительными, и префикс зависит
от окружения: локально `/media/…`, на проде `/girl-history/media/…`. Брать `photoUrl` и
`images[].url` из ответа как есть.

Всё с префиксом `VITE_` **вшивается в бандл** и видно в исходниках страницы. Секретам там не место.

## Доступ: три разных ключа

Входа и регистрации нет.

| Ключ          | Где живёт             | Что даёт                               |
| ------------- | --------------------- | -------------------------------------- |
| `ownerKey`    | localStorage браузера | видеть свой список профилей            |
| `ownerToken`  | приходит с профилем   | менять и удалять профиль, хроники, дни |
| `publicToken` | приходит с хроникой   | только чтение одной хроники            |

`ownerKey` выдаёт сервер в заголовке ответа при первом обращении, фронт его сохраняет.
**Очистка localStorage = потеря доступа ко всем своим профилям**: больше он нигде не хранится.
Ключ правки показан на вкладке «Профиль», его можно скопировать и сохранить.

`ownerToken` — не ссылка для передачи, а право удалить профиль со всем содержимым.
Делятся `publicToken` конкретной хроники.

## Как пользоваться

1. **Новый профиль** — имя и промпт: кто она, чем занимается. Персонаж произвольный.
2. **Референсы** (необязательно) — фотографии, которые должны повлиять на текст. Каждая
   разбирается моделью зрения, и в промпт идёт **полученное описание**, а не сама картинка.
   Нет референсов — хроника строится по одному промпту. Это и есть выбор «фото + промпт либо
   просто промпт», отдельного переключателя нет.
   Фото без описания (разбор не удался) **в генерации не участвует** — такие помечены,
   разбор можно повторить или вписать описание руками.
3. **Хроника** — период (пресеты 7/30/90 или любое число от 1 до 90), опционально дата начала,
   разовое пожелание и провайдер. Генерация фоновая, прогресс на той же вкладке.
4. **Лента** — дни с правкой и выборочной регенерацией.

Аватар профиля — **только оформление**: в LLM не отправляется и на текст не влияет.

| Команда              | Что делает                                      |
| -------------------- | ----------------------------------------------- |
| `pnpm dev`           | dev-сервер на `127.0.0.1:5174`                  |
| `pnpm build`         | `tsc --noEmit` + сборка Vite в `dist/`          |
| `pnpm preview`       | локальный просмотр собранного                   |
| `pnpm run typecheck` | только проверка типов                           |
| `pnpm run lint`      | ESLint (type-checked, `no-explicit-any: error`) |
| `pnpm run format`    | Prettier — записать; `format:check` — проверить |

`build` намеренно включает `tsc --noEmit`: сама сборка Vite типы не проверяет.

## Деплой

Статика в `/var/www/girl-history-admin`, отдаётся nginx по пути `/girl-history-admin/`
на том же origin, что и API.

- `.github/workflows/ci.yml` — на PR и не-master: `install --frozen-lockfile` + `build`
  (внутри `tsc --noEmit`); линт и формат advisory.
- `.github/workflows/deploy-admin.yml` — на push в `master` и вручную. Preflight секретов,
  сборка с `VITE_API_BASE=/girl-history`, проверка префикса ассетов, SCP, атомарная подмена
  папки на сервере, `nginx -t` и reload.

**Что нужно сделать один раз, иначе выкат не заработает:**

1. Завести секреты репозитория (Settings → Secrets and variables → Actions):
   `SSH_HOST`, `SSH_USERNAME`, `SSH_PASSWORD`. Именно секреты **репозитория**, без
   `environment:` — иначе они придут пустыми и preflight откажет.
2. Поставить nginx-блок из `deploy/nginx/girl-history-admin.conf` в server-блок нужного домена,
   затем `nginx -t && systemctl reload nginx`. Workflow конфиг не разворачивает.

Проверить после первого выката:

```
curl -I https://<домен>/girl-history-admin/   # 200, страница админки
curl -I https://<домен>/                      # по-прежнему чужая админка Lisa AI
```

**`/var/www/admin` — чужая папка**: там рабочая админка соседнего проекта, которую nginx отдаёт
с корня домена. Её workflow делает `rm -rf /var/www/admin/*`; копировать его, не сменив путь,
значит снести чужой прод. Наш выкат туда не ходит вовсе.
